## 一、业务概述

### 1.1 模块定位

订单处理中心是电商后台管理系统的核心业务模块，负责管理订单的完整生命周期，包括订单创建、状态流转、审核流程、物流追踪、数据统计等关键功能。该模块与商品管理、会员营销模块紧密协作，构成完整的电商运营闭环。

### 1.2 核心业务流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           订单完整生命周期                                    │
├─────────────────────────────────────────────────────────────────────────────┤

│   [创建订单] ──► [待付款] ──► [已付款] ──► [已发货] ──► [已送达] ──► [已完成] │

### 1.3 订单状态机

| 状态码 | 状态名称 | 说明 | 允许操作 |
|--------|----------|------|----------|
| 0 | 待付款 | 订单已创建，等待用户支付 | 取消订单 |
| 1 | 已付款 | 支付成功，等待发货 | 发货 |
| 2 | 已发货 | 商品已发出，运输中 | 更新物流 |

| 6 | 退款中 | 申请退款中 | 审核退款 |

// 多条件组合筛选实现
function fetchOrders(params = {}) {
  let result = [...orders.value]
  
  // 关键词搜索（订单号/会员名模糊匹配）
  if (params.keyword) {
    result = result.filter(o =>
      o.orderNo.includes(params.keyword) ||
      o.memberName.includes(params.keyword)
    )
  }
  
  // 状态精确筛选
  if (params.status !== undefined && params.status !== '') {
    result = result.filter(o => o.status === params.status)
  }
  
  // 日期范围筛选
  if (params.startDate) {
    result = result.filter(o => dayjs(o.createdAt).isAfter(dayjs(params.startDate)))
  }
  if (params.endDate) {
    result = result.filter(o => dayjs(o.createdAt).isBefore(dayjs(params.endDate).add(1, 'day')))
  }
  
  // 分页处理
  const start = (page - 1) * pageSize
  result = result.slice(start, start + pageSize)
  
  return { list: result, total: result.length }
}
```

  if (step.status === 'rejected') return 'error'     // 已驳回

    } else {
      orderStore.approveOrder(order.value.id, pendingStep.step, rejectReason.value)

  }

### 4.3 数据统计逻辑

#### 4.3.1 实时统计计算

```javascript
const orderStatistics = computed(() => {
  const stats = {
    total: orders.value.length,
    pending: 0, paid: 0, shipped: 0, completed: 0, cancelled: 0,
    totalAmount: 0, todayAmount: 0, todayOrders: 0
  }

  const today = dayjs().format('YYYY-MM-DD')

  orders.value.forEach(order => {
    // 累计总金额
    stats.totalAmount += order.totalAmount
    
    // 今日数据统计
    if (dayjs(order.createdAt).format('YYYY-MM-DD') === today) {
      stats.todayAmount += order.totalAmount
      stats.todayOrders++
    }
    
    // 状态计数
    switch (order.status) {
      case 0: stats.pending++; break
      case 1: stats.paid++; break
      case 2: stats.shipped++; break
      case 4: stats.completed++; break
      case 5: stats.cancelled++; break
    }
  })

  return stats
})
```

#### 4.3.2 按日期统计

```javascript
function getDailyStatistics(startDate, endDate) {
  const stats = []
  let current = dayjs(startDate)
  const end = dayjs(endDate)

  // 遍历日期范围
  while (current.isBefore(end) || current.isSame(end, 'day')) {
    const dateStr = current.format('YYYY-MM-DD')
    
    // 筛选当日订单
    const dayOrders = orders.value.filter(o =>
      dayjs(o.createdAt).format('YYYY-MM-DD') === dateStr
    )

    stats.push({
      date: dateStr,
      orderCount: dayOrders.length,
      amount: dayOrders.reduce((sum, o) => sum + o.totalAmount, 0)
    })

    current = current.add(1, 'day')
  }

  return stats
}
```

### 6.1 技术复杂度评估

| 维度 | 复杂度 | 说明 |

| 业务逻辑 | ⭐⭐⭐⭐ | 状态机流转、审核流程、统计计算 |
| 数据结构 | ⭐⭐⭐ | 嵌套对象（订单→商品→物流→审核→历史） |
| 组件交互 | ⭐⭐⭐ | 搜索筛选、分页、弹窗、路由跳转 |
| 图表集成 | ⭐⭐⭐ | ECharts 双图表、响应式、数据转换 |

### 6.2 核心难点分析

#### 6.2.1 状态机管理

**难点**: 订单状态流转需要满足业务规则约束，防止非法状态转换。

**解决方案**:
- 定义清晰的状态常量 `ORDER_STATUS`
- 状态更新时自动记录历史 `statusHistory`
- 操作按钮基于状态条件渲染 `v-if="row.status === 1"`

#### 6.2.2 审核流程编排

**难点**: 多步骤审核流程需要支持顺序执行、状态回退、驳回处理。

**解决方案**:
- 使用 `approvalSteps` 数组存储审核链
- 通过 `el-steps` 组件可视化展示
- 计算属性 `hasPendingApproval` 判断是否有待审核项

#### 6.2.3 物流轨迹追踪

**难点**: 物流信息需要时间线展示，支持动态更新。

**解决方案**:
- 使用 `el-timeline` 组件展示轨迹
- 物流轨迹按时间倒序排列（最新在前）
- 发货时自动初始化物流轨迹

#### 6.2.4 数据统计聚合

**难点**: 多维度统计计算，需要高效处理大量数据。

**解决方案**:
- 使用 `computed` 计算属性缓存结果
- 单次遍历完成多项统计
- 按需计算日期范围统计
